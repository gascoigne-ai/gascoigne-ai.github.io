gascoigne 0.7.2 Quoted env values work again.

Commands that start with a quoted env assignment run through the hook again, and builtins like command are left alone.

go install github.com/gascoigne-ai/gascoigne-cli/cmd/gascoigne@latest

Starting fresh? Install it first. Coming from 0.7.1: a costs page, faster release notices.

What's new

Quoted env assignments run again

A command like NODE_OPTIONS="--max-old-space-size=4096" npm run build was rewritten to gascoigne exec -- NODE_OPTIONS="--max-old-space-size=4096" npm run build, so exec tried to start a program called NODE_OPTIONS=--max-old-space-size=4096 and failed with "executable not found". Quoted values, including ones with spaces, now stay in front of gascoigne exec, as unquoted ones always did. The same goes for DATABASE_URL="postgres://app@localhost/app?sslmode=disable" go test ./....

Fixes

  • A line the hook already rewrote is not wrapped a second time when it holds a quoted env value.
  • command, exec and time lines stay unwrapped: they are shell builtins or keywords, there is no program for exec to run.
  • New tests run each rewritten line next to the original under sh and compare output and exit status.

Upgrade

1. Install the new version

go install github.com/gascoigne-ai/gascoigne-cli/cmd/gascoigne@latest

Or download an archive from the release. The background server notices the new binary and restarts itself.

2. Nothing else to do

Nothing is migrated or removed. Agents pick up the fix with their next command.
