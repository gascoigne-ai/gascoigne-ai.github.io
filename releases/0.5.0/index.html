gascoigne 0.5.0 Prose, shortened by a local model.

Commands, logs and JSON were already folded. Now long paragraphs of text and markdown can be too: a small language model that runs on your machine drops the words that carry least, and keeps every number, path, flag and line of code. It is an experiment, off until you say yes.

go install github.com/gascoigne-ai/gascoigne-cli/cmd/gascoigne@latest && gascoigne setup -experimental

Starting fresh? Install it first. Coming from 0.4: the release notice fix and prebuilt binaries.

What's new

Prose compression with a local model

The model is an extractive compressor: it only chooses which words stay, so the output is always a subsequence of what you wrote, never a paraphrase. From the opening paragraph of gascoigne's own README (573 tokens to 519 over the whole sample page, 9.4%):

before  gascoigne is a token optimizer for LLM agents. It sits between an agent and
        what the agent reads (shell output, MCP tool results, web pages),
        shrinks it, and keeps every original in a local ledger so nothing is
        ever lost.

after   gascoigne is token optimizer for LLM agents. It sits between agent and
        agent reads (shell output, MCP tool results, web pages), shrinks it,
        and keeps every original in local ledger so nothing ever lost.

It is lossy, so the original stays in the ledger and gascoigne raw <id> prints it. Numbers, paths, flags, identifiers, negations, inline code and links are never dropped. Headings, tables, lists, quotes, code fences and aligned command output are left exactly as they were. Expect 8–10% fewer tokens on prose-heavy text and nothing on code, tables or command output.

No Python, no cgo, any GPU you have

The model runs inside gascoigne itself. ONNX Runtime is opened at run time, so the binary is still a static, pure-Go build. It uses CUDA on Linux and Windows, CoreML (Metal and the Neural Engine) on macOS, and falls back to the CPU. The background server keeps it loaded between runs and frees it, and its GPU memory, after five idle minutes.

Setup downloads it, and shows what it downloads

Say yes to "Prose compression with a local model" in gascoigne setup and it fetches the model (601 MB) and ONNX Runtime for your platform. Every file is checked against a pinned SHA256 and the hashes are printed, so you can compare them with the ones in the guide. gascoigne prose status says whether it is ready.

$ gascoigne prose install
gascoigne prose: onnxruntime-linux-x64-1.29.0.tgz
  sha256 c3fddc4f139a045b0c4902c57410f0694f1c2fdf9b6939fbe38b1aeae7cd14ba
  downloaded, checksum matches
$ gascoigne prose status
prose: ready (model files in ~/.cache/gascoigne/prose-model)

See it in the dashboard

Runs the model shortened carry a prose −N tag in the recent runs table, and their details say how many tokens it dropped. An Experiments panel lists every experimental feature that is on, with the model's state and savings. The prose pass is its own optimizer, so gascoigne gain -by optimizer shows it apart.

A tidier dashboard

Nine tables became two tabbed panels: Models and cost (model families, models, API requests by day and by model) and Breakdown (command, optimizer, content type, runs not optimized, excluded sources). The tab you pick is remembered.

Evals you can watch

make eval-experimental runs the opt-in features on their own fixtures and writes the runs to your ledger, so they appear in the dashboard under the agent eval. The default eval stays independent of your experimental choices.

Upgrade

1. Install the new version

go install github.com/gascoigne-ai/gascoigne-cli/cmd/gascoigne@latest

Or download an archive from the release. The background server notices the new binary and restarts itself.

2. Bring your setup current

gascoigne upgrade

Your config.yaml moves onto the new template, settings kept.

3. Try prose compression

gascoigne setup -experimental

Answer yes to the prose question; it downloads the model. Needs a few hundred MB of memory while it runs.
